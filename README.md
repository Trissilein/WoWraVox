# WoWraVox

WoWraVox is a World of Warcraft Retail addon for Heroism, Bloodlust, Time Warp, buffs, debuffs, trinkets, spell cooldowns, and spoken or on-screen notifications.

## Version

Current stable version: **0.11.0**.

## What it does

- **Aura rules** watch your player buffs, debuffs, and item-effect auras. Self-only buffs such as defensives are announced in combat from your own cast; auras the addon cannot read in combat can play a native category word (Defensive, Offensive, Bloodlust) or a selected sound through the game.
- **Item rules** announce when an equipped item becomes ready after its cooldown. They track a fixed item or, in slot mode, whatever is equipped in a slot (for example Trinket 1).
- **Skill rules** announce when a Spellbook ability or a returning charge becomes ready.
- Speaks through WoW Text-to-Speech with a per-rule voice, speed, and volume. Announcements raised in the same frame with the same voice are spoken as one sentence.
- Shows independent on-screen Apply, Expire, and Ready text with per-text font, size, style, color, and draggable anchor.
- Searches spell names, including partial names for other classes, with a client-built local index; also accepts comma-separated spell IDs.
- Offers tooltip IDs, a rule preview, and access from the addon compartment, Titan Panel, or any LibDataBroker display.
- Diagnostics: `/wvdebug on|off|clear|show`, `/wvttstest <rule>`, and `/wvprof` (load times and, after `/wvprof on`, per-event timing).

## First launch

A new profile starts with these rules and nothing else:

1. **Heroism / Bloodlust** is a built-in aura rule (buffs plus the Sated family, which stays readable in combat). It is active, cannot be deleted, and announces the start once and the end once.
2. **Defensives** is an empty aura rule ready for your spell IDs (off until you fill it).
3. **Trinket 1** and **Trinket 2** are item rules for the two trinket slots. They follow whichever trinket you wear and announce when it is ready again.

These rules are created only for a new profile. Existing WoWraVox settings are preserved and never replaced.

## Usage

- `/wowravox` or `/wvr` opens WoWraVox; so does the addon compartment entry or a Titan Panel / LibDataBroker button.
- Select **Add rule** to create an Aura, Equipped item, or Spell cooldown rule.
- An equipped-item rule can hold several items or slots (**Add item**); each announces on its own when its cooldown ends, `{item}` and `{slot}` in the message stand for the one that became ready, and an entry's tag switches between tracking the item and the slot it sits in.
- Settings are stored in profiles that can be assigned per character and per specialization.
- On-screen text profiles can be previewed, recolored, and independently anchored.

## Interface skins

The WoWraVox window can use one of two looks: **WoWraVox** (default, unchanged) or **Clean**. Pick one under the gear button (**Display options → Interface skin**) or with `/wvskin <wowravox|clean>`; `/wvskin` alone lists them, and `/wvskin errors` prints skin errors for troubleshooting. A change takes effect after `/reload` (the button and the slash command reload outside combat). The choice is stored in the active profile.

The Clean textures live in `Assets/skin/` and `SkinData.lua` is generated from them. To rebuild them from the design PNG set (default `.agents/ui-skin/out/assets`, or pass `--src <dir>`):

```
pip install pillow numpy
python tools/Build-SkinAssets.py
```

The build losslessly trims the stretched centre of nine-slice textures to a small power-of-two strip (the game stretches it anyway) and verifies it by stretching each trimmed image back to the source PNG, pixel for pixel; textures whose centre is not uniform stay full size.

## Localization

English is the base language. German is included. Locale files live in `Locales/`; a missing translation falls back to English.

The spell-name index is generated by the WoW client on first use and saved locally for the current game build and language. No spell catalog is bundled with the addon.

## Installation

Copy this folder as `Interface/AddOns/WoWraVox`, then run `/reload` in WoW Retail.

Downgrading: from 0.10.0 on, settings live in `WoWraVoxProfilesDB`, and `WoWraVoxDB` is cleared at logout. An older version (0.9.8 or earlier) therefore starts with empty settings. Back up `WTF/Account/<account>/SavedVariables/WoWraVox*.lua` before downgrading.

### WowUp

In WowUp, open **Get Addons → Install from URL** and paste the repository URL: <https://github.com/Trissilein/WoWraVox>. Use the repository URL rather than a direct ZIP URL so WowUp can follow tagged releases for updates. Alternatively, search for **WoWraVox** with the Wago provider enabled.

## Development

Personal game settings live in WoW `SavedVariables` and are intentionally excluded from Git. Validate, deploy only addon files, compare hashes, then test `/reload` and BugSack in the Retail client.

Checks (run from the repository root):

```
python tools/Test-LuaSyntax.py                      # Lua 5.1 syntax + locals headroom (pip install lupa)
node tools/Test-AuraSoundFallback.js                # one harness per tools/Test-*.js (Fengari)
node tools/Test-SkillCharges.js
node tools/Test-TargetNotifications.js
node tools/Test-Skin.js
pwsh tools/Test-DailyRelease.ps1 -Version <v>       # version, README, CHANGELOG, tag, repo hygiene, and same-day gate
pwsh tools/New-ReleaseArchive.ps1 -Version <v>      # builds release/WoWraVox-<v>.zip and checks it against the TOC
pwsh tools/Get-ChangelogSection.ps1 -Version <v>    # release notes used for GitHub, Wago, and CurseForge
pwsh tools/New-ListingText.ps1                      # drafts the store descriptions and checklist into .agents/listing/
```

The release gate also checks that no working files (handoffs, backups, local agent notes) are tracked or about to be committed. Wago and CurseForge only accept files and a changelog through their APIs, so their descriptions, screenshots, and logo are updated by hand using the generated checklist.

The Node harnesses load Fengari (`npm install fengari`) from the path in `WOWRAVOX_FENGARI`, which must point at `node_modules/fengari`.

### Daily release policy

Development and approval happen locally first. Approved changes remain local until an explicit **release today** instruction. A release bundles all approved task-owned changes, runs the verification gate, updates the TOC, this version line, and `CHANGELOG.md`, then commits, creates an annotated `v<version>` tag, and pushes once.

Run `./tools/Test-DailyRelease.ps1 -Version <version>` before committing. It checks version consistency and blocks a second Stable release on the same Europe/Berlin calendar day. Versioning stays pre-1.0 semantic: patches for fixes and polish, minor versions for additive user-facing capabilities. The tag publishes Stable files to Wago and CurseForge and attaches the ZIP to the GitHub Release used by WowUp. On every push to `main` and on pull requests, `.github/workflows/ci.yml` runs the same checks and builds the ZIP without uploading anything.

If a platform upload fails, keep the version and tag. In **Actions → Release WoWraVox → Run workflow**, enter that version and select only the failed platform. The workflow requires the existing tag and resumes that exact release rather than creating another Stable version.
